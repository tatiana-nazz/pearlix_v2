# Phase 14C.0 QA — Team Profile API and Account Linkage Foundation

## Scope

Phase 14C.0 completed the backend and frontend-contract foundation separating professional Team records from Users & Access accounts. It added no runtime `/admin/team` route, Team detail route, sidebar item, shell change, Lucide dependency, or visual redesign. Final Team and Users & Access runtime UI remains Phase 14D; browser QA remains pending.

## Implemented backend endpoints

- `GET`/`POST /api/team-members/`
- `GET`/`PATCH /api/team-members/{id}/`
- `POST /api/team-members/{id}/set-professional-status/`
- `POST /api/users/{id}/transition-role/`
- `POST /api/users/{id}/reactivate/`

Team uses `User.id` as its stable identifier. All Team endpoints are Admin-only; unauthenticated, Staff, and Doctor callers are denied. List coverage includes pagination plus `q`, role, professional-status, and availability filters; Admins and legacy unlinked professional accounts are excluded.

## Contract coverage

- Transactional Doctor and Staff onboarding creates the account and exactly one matching professional profile, applies temporary-password state, validates duplicate email/password/profile payload errors, rejects unknown fields, and rolls back invalid requests.
- Professional update and professional-status actions require profile `version`; missing versions return `VERSION_REQUIRED`, stale versions return `VERSION_CONFLICT`, account fields are rejected, and professional status does not change login status.
- Generic `/api/users/` creates Admin accounts only. Doctor/Staff requests return `PROFILE_REQUIRED` and use `/api/team-members/`; generic role PATCH cannot bypass `transition-role`.
- User summaries expose linked-profile state and valid `team_member_id`; legacy unlinked professional accounts are `PROFILE_SETUP_REQUIRED` and remain outside Team.
- Transition preview/confirmation covers signed expiry/tamper/stale protection, self-role protection, last-active-Admin protection, safe supported transitions, and `ROLE_TRANSITION_BLOCKED_BY_HISTORY` when shifts, leave, appointments, or visits must be preserved.
- Reactivation is Admin-only for inactive, profile-consistent accounts; already-active and inconsistent states are rejected. It changes login activity only, never professional status.
- Audit metadata for Team creation/update/status, role transition, and reactivation is sanitized: no passwords, temporary passwords, confirmation tokens, or secrets.

## Integrity, migration, and demo coverage

`accounts.0005_doctorprofile_version_staffprofile_version_and_more` adds User and profile versions. `python manage.py check_profile_integrity --strict` reports dual-profile, mismatch, and active-Admin-profile violations without altering data. The Phase 14A demo story now seeds four Doctors with supported specialties/phones/bios and two Staff with supported positions/phones while preserving login/professional-status separation.

Frontend contract coverage is limited to `src/types/team.ts`, `src/api/endpoints/team.ts`, query keys, user linkage fields, and focused endpoint-wrapper tests. No runtime Team route or page was added.
