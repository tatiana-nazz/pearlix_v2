# Phase 13E.1 QA - Patient Schema and Version Contract

Status: documentation complete; browser QA execution remains pending.

## Scope

- Patient schema uses `first_name`, `last_name`, computed `full_name`, `gender` (`Male` or `Female`), optional `date_of_birth`, computed `age`, `phone_number`, `email`, `national_id_or_passport`, `address`, `emergency_contact`, `blood_group`, `medical_conditions_history`, `insurance_info`, `general_notes`, `is_archived`, and `version`.
- `national_id_or_passport` is optional. Blank values are sent as `null`; duplicate non-null values should show a validation error.
- Create does not send computed/backend-controlled fields: `full_name`, `age`, `is_archived`, `version`, audit users, or timestamps.
- Update, archive, and unarchive send the current `version`.
- Direct `is_archived` patching is not used by the frontend.

## Staff Browser QA

- Log in as Staff.
- Open `/staff/patients`.
- Search by name, phone number, email, and national ID/passport terms.
- Create a patient with required identity fields and optional contact/clinical fields.
- Verify the profile header shows computed full name, phone, age state, gender, status, and actions.
- Edit the patient profile and confirm the request succeeds with versioned payload behavior.
- Open two tabs for the same patient, save a change in one tab, then save stale edits in the other tab. Confirm the stale tab shows a conflict message and keeps local edits visible.
- Archive and unarchive the patient from the profile or list. Confirm both actions use the current version and refresh patient data.
